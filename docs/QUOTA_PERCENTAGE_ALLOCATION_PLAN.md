# OpenAI OAuth 用户配额百分比分配计划

## 1. 目标与范围

在当前分支实现“按 OpenAI OAuth 账号上游配额百分比，在用户之间进行分配和限制”。

第一阶段只支持以下场景：

- 平台：OpenAI；
- 账号类型：OpenAI OAuth；
- 一个分组只绑定一个 OpenAI OAuth 账号；
- 用户通过当前分组使用该账号；
- 分配单位使用当前系统已经校准的实际消耗金额 `ActualCost`；
- 使用 OpenAI 上游当前配额窗口的实时使用比例进行整体折算。

第一阶段明确不处理：

- 多账号分组、换号、故障转移和跨账号配额迁移；
- 固定份额加弹性借用；
- 按请求预估金额或预留配额；
- 由于单次大请求造成的瞬时超限；
- 其他平台的配额百分比分配。

## 2. 核心规则

用户在一个窗口内的估算使用比例为：

```text
用户窗口估算使用比例
= OpenAI 账号当前窗口整体使用比例
  × 用户在当前分组窗口内的消耗金额
  ÷ 当前分组窗口内所有用户的消耗金额
```

分别对两个窗口计算：

```text
用户 5h 估算比例
= 上游 5h 使用比例 × 用户 5h 消耗金额 ÷ 分组 5h 总消耗金额

用户 7d 估算比例
= 上游 7d 使用比例 × 用户 7d 消耗金额 ÷ 分组 7d 总消耗金额
```

用户配置的配额百分比同时用于 5h 和 7d 窗口。请求前只检查当前已经产生的消耗，不预测本次请求金额：

```text
用户 5h 估算比例 <= 用户配置比例
并且
用户 7d 估算比例 <= 用户配置比例
```

满足条件才允许请求。

## 3. 统计口径

### 3.1 金额

用户金额和分组总金额必须使用同一口径，即当前分组已经校准过的实际消耗金额 `ActualCost`。不使用：

- 用户余额扣款金额；
- API Key 自身配额金额；
- 不同销售或展示口径的金额；
- 未经统一校准的账号成本金额。

### 3.2 时间窗口

金额统计必须落在 OpenAI 当前窗口内：

- 5h：以上游当前 5 小时窗口起点为边界；
- 7d：以上游当前 7 天窗口起点为边界。

当上游窗口重置后，本地用户金额和分组总金额也必须使用新窗口重新统计，不能混入旧窗口历史金额。

### 3.3 零金额分母

如果当前窗口的分组总消耗金额为 0，则当前用户窗口消耗比例视为 0，允许请求。

## 4. 上游配额数据

OpenAI OAuth 配额查询使用现有 `/wham/usage` 能力，读取：

- 当前 5h 使用比例；
- 当前 7d 使用比例；
- 对应窗口重置时间；
- `limit_reached` 状态。

计算时以当前可获得的上游数据为准。本地金额只用于计算分组内部用户之间的金额占比：

```text
账号整体用了多少：以上游当前比例为准
用户之间如何分摊：以本地当前窗口金额占比为准
```

不使用固定历史校准因子，也不根据旧快照推算新的长期比例。

如果上游明确返回账号整体 `limit_reached = true`，则整个分组停止放行，不再单独判断用户比例。

## 5. 请求链路

请求进入当前分组后：

1. 确认分组只有一个 OpenAI OAuth 账号；
2. 确认当前用户的配额百分比配置；
3. 获取该账号当前 5h / 7d 上游配额状态；
4. 以当前两个窗口的起点统计用户 `ActualCost`；
5. 统计当前分组两个窗口的总 `ActualCost`；
6. 分别计算用户 5h / 7d 估算比例；
7. 检查是否超过用户配置比例；
8. 未超过则继续现有请求流程，超过则拒绝请求。

请求完成后的实际金额仍按现有计费和用量记录流程写入，作为后续窗口计算的数据来源。

## 6. 实现阶段

### 阶段一：规则和数据读取

- 确认分组单账号约束；
- 增加用户在分组上的配额百分比配置和读取；
- 复用现有 OpenAI OAuth `/wham/usage` 查询及窗口解析；
- 复用现有用量日志的 `ActualCost` 统计能力。

### 阶段二：请求前限制

- 在当前分组请求鉴权/额度检查路径加入 5h / 7d 比例检查；
- 处理零分母、窗口重置和账号整体 `limit_reached`；
- 保持现有美元订阅额度、余额、API Key 配额逻辑不变；
- 增加单元测试和数据库集成测试，覆盖窗口边界与并发读场景。

### 阶段三：管理端和用户可见信息

- 管理员配置用户配额百分比；
- 展示当前用户在 5h / 7d 窗口中的金额、金额占比和估算使用比例；
- 展示限制原因；
- 增加审计和运维日志。

## 7. 当前设计原则

- 金额是消耗单位；
- 分组金额已校准，所有用户使用统一评判标准；
- 上游比例与本地金额按实时当前窗口结合计算；
- 不做请求金额预测；
- 不提前预留配额；
- 不处理当前消耗未包含本次请求而导致的瞬时超限；
- 先完成严格的百分比分配，再考虑固定份额、弹性借用和多账号场景。
